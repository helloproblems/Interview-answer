# 原始任务与本次交付范围

## 业务背景（任务书原文）

某工业能源管理平台为企业提供电气设备状态监控与异常告警派单服务。系统监测到指标偏离阈值时，会自动为一线运维工程师生成现场检修工单。近期运维团队反映，很多检修任务到达现场后发现设备运转正常，耗费了大量工时。平台希望减少运维人员因误告警导致的现场空跑。

## 发放数据

`inspection_tickets.csv`，961 行，八个字段：

- `ticket_id`：工单唯一流水编号。
- `ticket_time`：异常告警触发生成现场检修工单的时间。
- `last_telemetry_time`：触发告警时系统依据的底层遥测数据最后同步时间。
- `region`：设备所属的运维片区。
- `device_type`：产生告警的电气设备类别。
- `reported_health_score`：告警时系统计算的健康评分，分值越低代表状况越差。
- `rated_power_kw`：该设备的额定功率，单位千瓦。
- `fault_confirmed`：现场排查是否确认存在真实故障，1 为确认故障，0 为空跑误报，空为未回传。

口径：每次现场空跑约损失 **120 工时**；每提前拦截复核一次约花费 **12 工时**。本项目沿用题设单位，不转换为分钟或设备停机时间。

## 用户补充目标（原文）

> 根据有限的数据进行数据模型训练项目构建，训练fault_confirmed，以确保后续根据信息进行是由有效故障的判断

据此交付可复现的监督学习训练、模型文件、批量预测命令和业务评估。有限历史样本只能验证特定时间段的表现，不能保证未来每次判断正确。
